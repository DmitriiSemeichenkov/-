# Управление требованиями

## Цель
Обеспечить единый процесс фиксации, согласования и изменения требований.

## Типы требований
- Бизнес-требования
- Функциональные требования
- Нефункциональные требования
- Ограничения и допущения

## Шаблон требования

```md
### REQ-0001: Краткое название
- **Источник:** (кто инициировал)
- **Приоритет:** High | Medium | Low
- **Статус:** Draft | Approved | Implemented | Archived
- **Описание:**
- **Критерии приемки:**
  - [ ] ...
  - [ ] ...
- **Связанные артефакты:** ADR / задачи / тест-кейсы
```

## Процесс
1. Добавьте требование в PR.
2. Пройдите ревью со стейкхолдерами.
3. Зафиксируйте статус и дату изменений.
4. Свяжите требование с задачами и тестами.
5. При изменениях обновляйте историю.

## Трассируемость
Для каждого требования фиксируйте ссылки на:
- задачу в трекере;
- коммит/PR с реализацией;
- тесты или критерии проверки.
