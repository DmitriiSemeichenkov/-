# Документирование

Шаблон проекта для подхода **Documentation as Code**: документация хранится рядом с кодом, проходит ревью через Pull Request и версионируется в Git.

## Что уже настроено

- Стартовая структура папок `docs/`.
- Набор шаблонов для основных видов документации.
- Простая веб-страница (`index.html`) как локальный портал по документации.
- Рекомендации по процессу обновления документации.

## Структура

```text
.
├── docs/
│   ├── README.md
│   ├── architecture.md
│   ├── decisions/
│   │   └── README.md
│   ├── guides/
│   │   └── onboarding.md
│   └── runbooks/
│       └── incident-response.md
├── app.js
├── index.html
├── style.css
└── README.md
```

## Как использовать

1. Ведите документацию только через Pull Request.
2. Для архитектурных решений добавляйте ADR в `docs/decisions/`.
3. Для эксплуатационных сценариев поддерживайте runbook'и в `docs/runbooks/`.
4. Для обучения команды обновляйте `docs/guides/`.

## Локальный просмотр

Откройте `index.html` в браузере — это удобная стартовая страница для навигации по документации.

## Рекомендуемый workflow

- Создавайте ветку под изменение документации.
- Обновляйте затронутые разделы и добавляйте дату изменений.
- Делайте PR с понятным описанием «что/зачем».
- После мержа публикуйте документацию (например, через GitHub Pages, MkDocs или Docusaurus).
